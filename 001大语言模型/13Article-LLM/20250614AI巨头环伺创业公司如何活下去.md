作为最热门的 AI 赛道之一，AI 不仅吸引了最广泛的资本和关注，也吸引了最激烈的竞争。

伴随着 Anthropic 暂停了 Windsurf 的模型访问。在 AI 模型巨头环伺的环境中创业公司如何活下去，这个问题也成了创业不得不重新面对的问题。

Anthropic 公司首席产品官 Mike Krieger 在 Lenny's Podcast 最新一期节目中也谈到了这个问题。

当前，在编程基准测试 SWE-Bench 上，AI 模型的能力已经达到 50%，如今已经达到 72%。模型的能力提升已经是必然。

对创业者而言，如今更应聚焦于如何最大化利用 AI 能力。

他观察到，最成功的公司都有一个共同特点：他们一直在尝试用 AI 解决那些「几乎能做到但还差一点」的任务。这些公司在 Claude 3.0 时就开始尝试，即使频频碰壁；当 3.5 版本发布时，他们的产品突然变得可行；到了 Opus 4，他们的工程师会惊呼「我从没见过这样的表现」。只有持续挑战模型的极限，才能在新版本发布时获得真正的突破。

Krieger 认为，如今，巨头环伺，创业公司更应该深耕垂直行业的专业知识（如法律、医疗的特定流程和合规要求）；建立差异化的市场推广能力（深入了解具体决策者而非仅了解公司）；创新交互界面（做出起初看似前卫但最终成为主流的设计）；保持创业公司的战斗精神（那种「每天都感觉生存攸关」的紧迫感）。

锦秋基金（微信公众号：锦秋集，ID：jqcapital）认为，作为领先 AI 公司的首席产品官，Krieger 提供了从瓶颈转移到竞争策略，从产研融合到边界创新的前沿的洞察，这些思考对所有希望理解 AI 如何重塑产品开发的创业者和产品人都极具参考价值，因此做了编译。

### 01. AI 编程的革命性变化

Mike Krieger 透露了一个让人震惊的数字：Anthropic 现在九成的代码都是 AI 写的。要知道，几年前这个数字还是零。他们的工程负责人说，超过一半的代码提交是 Claude Code 生成的，现在这个比例可能已经到了七成以上，完全超出了大家的预期。

更有意思的是，Claude Code 团队的工作方式简直是套娃 —— 他们用 Claude Code 来开发 Claude Code 本身。Mike 估计，这个项目里可能有 95% 以上的代码都是 Claude Code 自己写的。

要知道，Claude Code 是用 TypeScript 写的，这其实是 Anthropic 最大的 TypeScript 项目。而 Anthropic 本身主要用 Python，再加上一些 Go 和 Rust，并不是一家以 TypeScript 为主的公司。

这样做不仅效率高，还让新人加入项目变得特别容易。Mike 讲了个有趣的例子：有个同事在 Slack 里抱怨 Claude Code 的某个功能让他很头疼，他说：「我根本不会 TypeScript，我就直接问了 Claude。」结果呢？他从零开始，一个小时就搞定了代码提交，把问题解决了。

现在参与项目不需要先精通某种语言了，团队也可以根据具体任务选最合适的编程语言，而不用受限于大家的技术栈。

### 02. 产品开发流程的巨变

当 AI 写了这么多代码之后，传统的产品开发流程被彻底颠覆了。以前是产品经理定需求，工程师写代码，然后部署上线，瓶颈通常卡在工程实现这一步。虽然现在工程师的角色已经发生了很大变化，但参与产品开发的人员配置还没完全跟上 —— Mike 觉得这其实是个问题，因为大家还在用老思路做事。

现在 Mike 最喜欢的一个变化是，有想法的产品经理或设计师会直接用 Claude，甚至用 Artifacts 做出能跑的演示。这让想法一下子变得具体起来。原型制作通过代码加设计的方式，在流程中出现得更早了 —— 这可能是角色转变最大的地方。

不过 Mike 也强调，怎么跟 AI 对话、怎么构建问题、怎么理解前后端的架构 —— 这些仍然是很专业的技能，还是需要工程师来把关。就像经典的流程优化书《目标》里说的，解决了一个瓶颈，新的瓶颈就会在别的地方冒出来。

现在新的瓶颈出现在两个地方：

一个是前期的决策和协调。Mike 说：我现在想得最多的是，怎么给团队一个最简单的策略框架，让大家都能放手去试、去建、去探索模型的能力边界。我觉得还没完全做好，但正在努力。

另一个是后期的代码合并和部署。因为代码生成太快了，Anthropic 不得不重新设计整个代码合并系统 —— 就是那个负责把代码改动排队部署到生产环境的系统。提交的代码量暴增，完全超出了原来系统的设计能力。Mike 打了个比方，说这就像「空中交通管制」，要协调所有这些代码安全落地。

代码审查的方式也完全变了。Claude Code 团队刚开始还像其他项目一样逐行审查代码，但很快发现 Claude 写的代码通常都没问题，而且它生成的代码量太大，人工逐行看根本看不过来。所以现在的做法是：让另一个 Claude 来审查代码，人类主要负责验收测试，而不是逐行检查。这种方法有好有坏，但目前看来效果还不错。

### 03. 给 AI 创业者的建议

「我们会不会被大型 AI 公司碾压？」这是 Mike 在创业者聚会上听到最多的担忧。无论是在 Menlo Ventures 还是 Y Combinator 组织的活动上，创始人们都在问同一个问题。Mike 的回答很坦诚：短期内看 —— 比如未来一到三年 —— 有几个方向还是相对安全的。至于五年、十年后会怎样？他也说不准。

第一个方向是专注垂直领域。Mike 讲了个有意思的经历：法律 AI 公司 Harvey 团队给他演示产品界面时，他完全看不懂。「这都是些什么？」他问。对方笑着解释：「这是律师处理案件的专用界面。外行人根本想不到要这样设计 —— 你可能觉得这种工作方式很奇怪，但律师们就是这么干活的。而这恰恰是 AI 能帮上忙的地方。」

关键在于懂行。Mike 特别看好生物技术领域，那些把 AI 和生物技术结合得好的公司让他很兴奋。他甚至幻想过一个场景：如果实验室的设备都能支持 MCP 协议，那就可以用 Claude 直接操控这些仪器了。

当然，法律、医疗这些领域也都有自己的门道，各种合规要求让外人望而却步。这些方向听起来可能不太性感，但 Mike 认为，正是这些「无聊」的领域能孕育出真正的大公司。

第二，建立差异化的销售能力。这不仅仅是了解你要销售给哪家公司，更重要的是理解公司内部的决策链条。正如 Anthropic 的产品负责人 Michael 经常强调的：「你必须知道自己在向公司里的哪个具体角色销售。」

不同的决策者有着完全不同的关注点 —— 工程团队关心的是技术栈的选择和 API 的易用性，CTO 考虑的是整体技术战略，CFO 关注投资回报率，而法务部门则担心合规风险。只有深入理解这些差异，才能真正打动你的目标客户。

当然，建立这种深度理解并非易事。如果你来自目标行业，或者与行业内人士共同创业，这会是一个巨大优势。即使没有这样的背景，也可以通过持续的客户交流逐步积累这种洞察。关键是要有耐心和决心去真正理解客户的世界。

第三，界面创新的机会。ChatGPT 虽然拥有数亿用户，但这种成功也带来了局限性 —— 用户已经形成了「AI 就是对话框」的固定认知。这恰恰为创业公司提供了机会：通过创造全新的交互方式来定义人们与 AI 互动的未来。Mike 对此充满期待，他认为那些敢于突破传统对话界面、探索全新交互形式的创业公司将大有可为，尽管目前这样的公司还不多。

为什么这是个机会？因为你可以从一个看似小众的创新开始 —— 也许是语音优先的交互、也许是与物理世界结合的界面、也许是完全不同的视觉呈现方式。这些创新起初可能只吸引极客用户，但随着 AI 模型能力的提升，原本复杂的交互可能变得异常简单和自然，从而引发用户的大规模迁移。而大公司很难快速转向，因为他们需要维护现有用户的使用习惯，这种包袱反而成为创业公司的竞争优势。

第四，保持创业公司的战斗精神。在与大公司竞争时，创业公司最容易被忽视的优势其实是那种「生死存亡」的紧迫感。Mike 以自己的经历为例：在 Instagram 时期，他们只有两个人，每天都在想「看看我们能创造什么奇迹」；在 Artifact 时期，团队也只有六个人，但每个人都怀着「这件事做不好就活不下去」的决心。这种紧迫感驱动着团队以超常的速度和专注度解决问题。

这听起来可能像陈词滥调，但 Mike 强调，这种精神是大公司无法通过 OKR 或任何管理工具复制的 —— 它必须是真实的生存压力。当你真的相信「不成功便成仁」时，你会以完全不同的方式工作。这不是一个具体的产品方向，而是一种工作状态，但它确实能转化为持续的竞争优势。

### 04. 产品团队与模型团队的深度融合

在 Lenny's Friends 峰会上，Mike 与 OpenAI 的首席产品官 Kevin Weil 进行了一场备受关注的对话。Mike 分享了一个关键洞察：Anthropic 尝试了两种不同的产品开发模式 —— 一种是产品人员专注于用户体验优化，另一种是产品人员直接嵌入研究团队参与模型改进。结果令人意外：几乎所有的突破性进展都来自后者。

这个发现彻底改变了 Anthropic 的工作方式。Mike 解释道：「如果我们只是拿着现成的模型去做产品，那任何人都可以做同样的事。我们真正的价值在于深入模型层面，从根本上改变 AI 的能力边界。」这就是为什么产品人员需要参与模型训练的全过程 —— 从定义功能需求，到设计训练方案，再到测试和优化。

Artifacts 功能的开发完美诠释了这种方法的威力。传统做法是产品团队拿到模型后想办法包装成功能，但 Anthropic 的做法截然不同：他们让产品经理与负责代码能力训练的研究员组成小组，共同思考「如何让 Claude 不仅能写代码，还能以用户最需要的方式呈现代码」。这种深度合作产生的不是简单的功能叠加，而是模型能力与用户需求的有机融合。

我们已经不再区分「模型开发」和「产品开发」了，Mike 总结道，「每个新功能都是从训练阶段就开始设计的。产品经理参与决定模型应该学会什么，研究员理解用户真正需要什么。这种双向融合创造出的产品，是任何单纯调用 API 的团队都无法复制的。」

### 05. 竞争格局与差异化战略

当被问及如何看待 ChatGPT 在市场上的主导地位时，Mike 的回答出人意料地坦诚：「如果你在街头随机采访，问人们知道哪个 AI 产品，他们肯定会说 ChatGPT —— 甚至不是 OpenAI，而是 ChatGPT 本身。这个品牌已经成为了 AI 的代名词。」

但 Mike 并不认为 Anthropic 应该去追赶这种大众认知度。他从 Instagram 的经历中学到了重要一课：爆款产品往往是可遇不可求的，刻意追求反而适得其反。「我们当然会继续开发有趣的产品，也许其中某个会意外走红。但如果把打造下一个 ChatGPT 作为核心战略，那就大错特错了。」

相反，Anthropic 选择了一条更符合自身特质的道路。「与其模仿别人的成功，不如发挥自己的独特优势。」

Mike 指出，Anthropic 已经在开发者社区建立了强大的口碑，但更重要的是，他们正在培育一个「构建者社区」—— 这不仅包括程序员，还包括所有喜欢用 AI 创造东西的人，无论是设计师、作家还是创业者。

这个战略的价值在一个意想不到的地方得到了验证。Anthropic 法务团队的一位同事给 Mike 发来邮件，兴奋地分享他如何用 Claude 为家人开发定制软件。「一个律师，用 AI 编程来解决生活问题，还通过这个过程与家人建立了新的连接，」Mike 感慨道，「这正是我们想要看到的 —— 让每个人都能成为构建者。」

展望未来，Mike 保持着谨慎的乐观：「AI 市场足够大，能够容纳几家具有时代意义的公司共同成长。关键不是抢夺市场份额，而是找到自己的独特定位。」

对 Anthropic 来说，这个定位很清晰：我们要成为那些想用 AI 创造价值的人的首选工具。无论是帮助他们完成几小时的复杂工作，还是实现他们的创意想法，我们的目是让 Claude 成为最得力的 AI 助手。这才是真正重要的 —— 不是成为最有名的 AI，而是成为最有用的 AI。

### 06. MCP：连接 AI 与世界的桥梁

Anthropic 最近推出了 Model Context Protocol（MCP），这是一个重要的创新。Mike 在介绍 MCP 时，用了一个简单的框架来说明 AI 产品的构成：要想让 AI 产品真正发挥作用，需要三个要素 —— 模型的智能、上下文与记忆、应用界面。这三者缺一不可。

而 MCP 要解决的正是中间这一环 —— 上下文与记忆。比如，当你问 AI「谈谈 Anthropic 的产品策略」时，如果 AI 只能上网搜索公开信息，得到的答案必然是泛泛而谈。

但如果 AI 能通过 MCP 访问内部的 Slack 对话、查看 Google Drive 里的文档，了解团队正在进行的讨论，那答案就完全不同了。有了正确的上下文，AI 才能给出真正有价值的回答。

MCP 的诞生源于一个痛点。Anthropic 团队在开发各种集成功能时发现，每次都要从零开始，没有任何可复用的部分。

两位工程师 Justin 和 David 提出了一个大胆的想法：为什么不制定一个标准协议？这样开发者只需要构建一次集成，就能被 Claude 使用，将来还能被 ChatGPT、Gemini 等其他 AI 使用。这不正是整个行业都需要的吗？

Mike 提到了 Joel Spolsky 的经典策略：「让你的互补产品变得便宜易得」。Anthropic 擅长的是构建 AI 模型，而不是做各种系统集成。作为市场上的后来者，他们很难说服开发者专门为 Claude 开发集成。但 MCP 改变了游戏规则 —— 开发者不再觉得是在为某一家公司做专属开发，而是在构建一个通用的解决方案。

Mike 的愿景是让 MCP 无处不在。他分享了一个生活中的小例子：有次他看到妻子在和 Claude 对话，生成了一些很好的内容，她说：「太棒了，你能把它保存到项目知识库里吗？」Claude 回答：「抱歉，我做不到。」但如果 Claude 的每个功能都通过 MCP 开放出来，这种简单的需求就能轻松实现。

### 07. 如何充分利用 Anthropic 的 API

谈到哪些公司最善于使用 Anthropic 的模型和 API 时，Mike 认为关键在于敢于挑战模型的极限。这些公司会不断尝试模型做不到的事情，然后在新版本发布时收获惊喜。

他特别欣赏那些说「3.5 版本终于让我们的产品成为可能」的公司 —— 这说明他们早就在尝试，即使之前碰壁了，也在坚持探索。这些公司知道模型虽然还不完美，但对特定用例已经足够好，可以先服务一小部分高级用户。

这次 Opus 4 发布前，Anthropic 扩大了早期测试的范围。原因很简单：虽然他们可以用 SWE-bench、MMLU 等标准测试来评估模型，但真正重要的是用户的实际体验。Cursor 有自己的使用标准（虽然不是正式的测试），Mensch、Harvey 等公司也都有各自的需求。这些才是 Anthropic 真正需要满足的。

Mike 给出了两条建议：第一，要勇于探索模型能力的边界；第二，建立一套评估体系，当新模型发布时，能够快速判断它是否真的带来了改进。这可以是传统的 A/B 测试，可以是内部评估，也可以是保存使用记录然后用新模型重新测试。

他分享了一个有趣的故事：在早期测试中，一位创始人听到旁边的工程师突然大叫。创始人问怎么了，工程师说：「这个模型太强了，我从没见过这样的表现！」那是 Opus 4。创始人说：「很好，我们要让用户也有这种感觉。」但 Mike 强调，只有当你真正在解决困难问题时，才能感受到模型能力的飞跃。

### 08. 时间线的加速与未来展望

谈到 AI 发展的时间线，Mike 提到了 Anthropic CEO Dario Amodei 的预测能力。Dario 曾说：「我做出的预测总是被人嘲笑，但后来都实现了。」确实如此。去年当 SWE-Bench 编程测试的成绩还在 50% 时，Dario 预测到 2025 年底会达到 90%。现在已经达到 72%，进展完全符合预期。

Mike 说他现在对这些预测更加重视了。他分享了一个特别的经历：有一次，他同时打开了两个标签页，一个是 Dario 写的《AI 2027》，另一个是自己的产品策略文档。那一刻他突然意识到，自己正在参与塑造那个未来。

虽然 2027 年听起来还很遥远，但现在已经是 2025 年中了，模型在持续进步，能够执行任务、保存记忆、长时间运行。Mike 对这个时间线越来越有信心，尽管具体会如何实现还不确定。

### 09. 为什么加入 Anthropic

被问到为什么选择加入 Anthropic 时，Mike 分享了他的思考过程。2024 年初，他明显感受到 AI 模型的快速进步。看着自己的孩子，他意识到他们将在一个充满 AI 的世界中成长，这是不可避免的。于是他问自己：在哪里能最好地利用自己的时间，推动事情朝着正确的方向发展？

这也是 Anthropic 许多人的共同想法。大家都在思考：什么样的人类 - AI 关系是理想的？如何衡量进展？在这个过程中需要构建什么？这些问题有的涉及产品设计，有的涉及研究和可解释性。对 Mike 来说，加入的最大动力是相信 Anthropic 能在引导 AI 良性发展方面发挥重要作用，而他希望成为其中的一份子。

### 10. AI 作为思维伙伴的突破

加入 Anthropic 后，Mike 对 AI 的认知发生了两个重要转变：一是对 AI 能力的理解，二是对发展时间线的判断。

关于能力，Mike 坦言：「我刚加入时认为，AI 模型虽然很强大，能生成代码，能模仿你的写作风格，但它们能有独立的洞察吗？」这个看法直到最近才改变，尤其是在 Opus 4 发布后。

现在，Claude 已经成为 Mike 首选的产品策略伙伴，这种合作关系已经持续了一整年。过去，当他把策略文档分享给 Claude 时，得到的往往是一些平淡的建议，让他觉得「这些我都想到了」。但 Opus 4 配合高级研究功能后，情况完全不同了。Claude 会深入研究后提出独到的见解，让 Mike 惊叹：「你真的从一个全新的角度看待了这个问题。」

这种创造性和新颖性是 Mike 没有预料到会这么快出现的。Claude 现在能够提供他之前没有考虑过的视角，而且这些洞察往往会立即被纳入他的思考框架中。

### 11. 重新定义产品指标

Claude 曾提出一个很有洞察力的问题：「当用户与 AI 的对话可能只有两条消息，也可能有两百条时，你该如何衡量产品的成功？当深度比频率更重要时，传统的用户参与度指标可能会产生误导。」

Mike 认为这确实是个关键问题。团队内部最近有过深入讨论，如果过度追求让 Claude 变得「受欢迎」，可能会带来问题：Claude 会不会变得过于讨好用户？会不会只说用户爱听的话？会不会为了延长对话而故意绕圈子？

他回忆在 Instagram 时期，使用时长是核心指标，后来发展为关注「健康的使用时长」。但对于 AI 产品，传统的参与度指标可能完全不适用。用户是每天使用、每周使用还是每月使用？这取决于具体的使用场景。

Mike 坦言还没有完美的答案，但他认为核心应该是：「AI 是否真正帮助用户完成了工作？」他举了个例子：Claude 帮他制作了一个原型，原本需要六小时的工作，20-25 分钟就完成了。这种价值很难用传统指标衡量。

「当产品真正为用户创造价值时，你能感受到。」Mike 说，「过度关注指标往往是因为产品本身不够好，需要数据来自我安慰。」他们的目标是持续听到用户说：Claude 帮助他们释放了创造力，提高了工作效率，让生活有了更多空间做其他事情。

### 12. 关闭 Artifact 的艰难决定

Mike 详细解释了为什么要关闭 Artifact —— 他之前创办的新闻阅读应用。尽管他自己至今还在怀念这个产品，也没找到合适的替代品，但确实面临着几个难以克服的挑战。

首先是移动网页体验的恶化。现在用户点击文章链接，迎接他们的是弹窗广告、自动播放的视频、各种订阅提示。Mike 不想通过广告拦截来解决这个问题，因为那样对内容创作者不公平，但用户体验确实很糟糕。

其次是产品缺乏传播性。Mike 回忆说，Instagram 早期能快速增长，是因为用户会把照片分享到其他平台。但新闻阅读是很私人的事情。「我记不清有多少次，用户告诉我我爱 Artifact，但当我问你推荐给朋友了吗？他们说就告诉了一个人。」任何试图增加社交功能的尝试都显得很生硬。

第三个容易被忽视的因素是远程工作的限制。团队在疫情期间组建，完全分布式办公。当需要进行重大战略调整时，远程沟通的局限性就显现出来了。Mike 怀念 Instagram 时期的深夜讨论：「那些艰难时刻，我和 Kevin 晚上 11 点在 Market 街的墨西哥餐厅，边吃卷饼边想办法解决问题。视频会议真的不是好的替代品。」

进入 2024 年，团队意识到虽然这个领域确实需要一家优秀的公司，但可能他们不是最合适的人选。Mike 总结说：「我们投入 10 分努力只能获得 1 分回报，而不是相反。」当 AI 开始改变一切时，机会成本变得越来越明显。

### 13. AI 时代的儿童教育思考

作为两个孩子的父亲，Mike 分享了他对 AI 时代教育的思考。他们家有个传统 ——「早餐提问时间」。大女儿快六岁了，经常会问一些关于太阳系或物理的有趣问题。

Mike 说，每当遇到这些问题，他的第一反应往往是「问问 Claude 怎么说」。但他们刻意改变了做法：「我们该怎么找到答案呢？」不能总是依赖 AI。可以做实验，可以观察，可以推理。虽然对六岁孩子谈「科学方法」听起来有些夸张，但培养探索精神和解决问题的能力依然重要。AI 是强大的工具，但探究的过程和独立思考不能丢。

他分享了一个有趣的小故事。有次女儿很肯定地说了什么（关于珊瑚是不是动物），Mike 不太确定，就说：「我不知道这对不对。」女儿坚持说：「这绝对是对的，爸爸。」Mike 说：「那我们问问 Claude 吧。」女儿回答：「你可以问，但我知道我是对的。」

「我喜欢这种自信，」Mike 说，「我希望孩子们保持这种独立性，而不是把所有思考都交给 AI。AI 不会永远正确，而且过度依赖会让人失去独立思考的能力。」

有意思的是，Shopify CEO Tobias Lütke 在谈到培养孩子什么能力时，给出了同样的答案：好奇心。

Mike 还提到，女儿学校最近请来了一位 AI 教育专家。他原本期望不高，但这位专家的开场让他印象深刻：「让我们从 Claude Shannon 和信息论说起。」看着其他家长困惑的表情，Mike 也在想：「这是要干什么？」但专家巧妙地引导大家理解：未来会有很多新工作，我们现在无法预测。重要的是培养孩子的核心能力、掌握底层技术、保持开放心态。这些东西在孩子们成年前可能会改变很多次。

这或许就是 AI 时代教育的关键：不是教具体的知识，而是培养学习和适应的能力。
