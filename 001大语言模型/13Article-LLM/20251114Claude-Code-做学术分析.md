## 20251114Claude-Code-做学术分析

2025-08-27

Claude Code 是一个 Agentic CLI，在极客圈非常受欢迎，它强大的编码规划能力和执行能力让使用过的程序员爱不释手。

我前段时间在公司内分享了 Claude Code （以下称 cc）的关键优点和实践，其中许多内容已经被越来越多使用者熟知，但其中有一点非常容易被工程师群体所忽略，那就是 cc 独特的可供性（Affordance）。

什么是可供性？可供性（Affordance）指的是一个物体或环境的属性，这些属性揭示了它能够被如何使用。简单来说，一件东西看起来能做什么，就是它的可供性。

作为一个 CLI 命令行工具，CC 的可供性看起来很弱，它的界面只是一个能在黑框中输出文本的光标，完全没有告诉你，可以输入什么命令，有什么用处。这对于新手来说，有巨大的认知障碍，它几乎不提供任何操作线索。

然而，作为一个 Agentic CLI，CC 的革命性在于，它重塑了交互的本质。交互不再是发出精确的指令，而是表达你的意图。它提供的可供性不再是「输入这条命令」，而是「告诉我你想要什么，我来尝试实现」。

例如，你对它说：「帮我分析这份笔记，并制作一个 5 页的 PPT。」这个任务在传统命令行里是不可想象的，但在 CC 里，它成了一种真实可行的操作。这种基于自然语言的交互容错性极高，你可以像和人对话一样，用多种方式表达同一个意图。这极大地降低了复杂任务的门槛，让「可能性」变得触手可及。

所以，从语言交互和实现复杂意图的层面看，CC 的可供性极强。

抛开成见吧，朋友，理解了可供性这一点，你才能认识到 Agentic CLI 的强大，它绝不只是程序员的锤子，而是任何人的助手。除了写代码，你完全可以用 cc 写 slides，处理图像，剪视频，做表格……

下面，我将分享一个全程使用 CC 完成的学术分析案例。

### 实践案例：用 Claude Code 研究一位顶尖学者

我的研究目标是深度学习领域的大牛 —— Yann LeCun。我需要下载他的全部论文，并尽可能搜集所有相关信息，包括专利、书籍、社会资助、社交媒体、演讲、播客等，然后将这些海量信息整理成标准格式，进行深度分析和网络分析，最终生成一份完整的报告并发布成网站。

在过去，这是一个无比繁重的工作。

我需要拼凑一个庞大的工具箱：用 Zotero 管理文献，用各种插件下载论文全文；用浏览器爬虫抓取谷歌学术和专利；用定制脚本爬取 Twitter、YouTube 等社交媒体数据；用 Bibliometrix 这样的科学计量软件做网络分析；再用一堆小工具做格式转换…… 整个过程需要在数十个软件间不断切换，耗时耗力。

而有了 Agentic CLI，我的角色从执行者转变为指挥官。

我只需统筹全局，将意图传达给 CC。当它遇到困难时，我研究一下实现方法，稍加点拨，它就能一步步完成我的设想。

### 第一步：自动化搜集全网数据

数据获取的核心无非是搜索和下载。我让 CC 使用其 web search 功能来完成。

首先，我需要 Yann LeCun 的所有论文。我从开放学术数据库 OpenAlex 导出了他的论文元数据列表。接着，我让 CC 根据每篇论文的唯一编码和标题，去 Sci-Hub 和 Google Scholar 检索并下载 PDF 全文。这背后的原理，与 Zotero 的某些下载插件类似，无法是去检索特定网站，我只需为 CC 提供 Playwright MCP server 即可搞定。

同样的方法也适用于其他数据源。无论是专利、图书、科研基金还是社交媒体信息，我只需告诉 CC 目标网站，它就能为我检索和下载。

当然，有些网站（如 Twitter）有反爬策略。直接抓取行不通，我便提供 Browsermcp server，授权 CC 使用我本机的浏览器。它能像我本人一样，登录我的账号，浏览页面，滚动加载，直到抓取到足够的数据。我需要做的，只是在一旁静静等待。

### 第二步：从混乱到有序的智能整理

搜集来的原始数据是杂乱的，需要结构化处理，包括编码、去重、分组和补全。这些任务大多可以通过简单的脚本实现。

例如，许多论文元数据缺少 DOI 编码。我指示 CC 访问 CrossRef 网站，根据论文标题和作者逐一检索，从而补全了大部分缺失的 DOI。对于其他需要归类和格式化的信息，同样可以用几句自然语言指令让 CC 编写脚本来处理，比如，将文件重命名，将论文按时间分组等。对于视频文件，甚至可以让 cc 使用 ffmpeg 对视频压缩和 transcript。

### 第三步：规模化深度分析

数据整理完毕，就进入了最核心的分析阶段 —— 阅读海量论文并提炼洞见。这恰恰是大型语言模型最擅长的。

只要预先建立好分析框架，就能事半功倍。我利用 CC 的「子代理」（sub-agent）功能，创建了五个专门的分析角色：

1 术语分析代理：负责提取和定义核心术语。

2 论证分析代理：负责梳理论文的论证结构。

3 问题分析代理：负责识别论文试图解决的关键问题。

4 写作分析代理：负责分析文章的写作风格与结构。

5 创新分析代理：负责评估论文的核心创新点。

这些子代理各自拥有独立的上下文，可以互不干扰地从不同维度分析同一篇论文。我甚至可以同时启动多个相同的子代理，并行处理多篇论文，效率极高。

### 第四步：一键生成研究报告与网站

经过前面的积累，我已经掌握了足够的数据和分析结果。

我首先用 /init 命令让 CC 全局回顾所有资料，然后给出一个研究主题，它便迅速生成了报告大纲。接下来，我让专门的「写作代理」填充各个章节的内容，并调用 Python 脚本库生成各种分析图表，甚至直接输出 Bibliometrix 代码完成科学计量分析。

最后一步，是将这份完整的文本报告转化为一个公开的可视化网页。这项任务对于精通代码的 Claude 模型来说，同样轻而易举。
