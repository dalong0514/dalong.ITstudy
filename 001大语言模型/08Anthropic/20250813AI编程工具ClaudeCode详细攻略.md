## 20250813AI编程工具ClaudeCode详细攻略

本期视频将介绍 30 个 Cloud Code 的高阶使用技巧，帮助您精通这款近期热度最高的 AI 编程工具。Cloud Code 在海外社区获得了大量讨论，上期视频我们介绍了在国内免费使用它的方法，本期我们将进入实战环节。

首先，如果您的电脑上没有安装过 Node.js，请点击视频中的链接先进行安装。然后，复制 Cloud Code 的安装命令，打开一个命令行窗口，将命令粘贴并执行安装。安装完成后，使用 `cd` 命令跳转到需要编写代码的项目目录。

启动 Cloud Code 有两种方式。如果您是 Cloud 官网的 Pro 或 Max 级别用户，可以直接输入命令 `cloud` 启动，并选择第一项去官网登录。另一种方式是接入 API。我在上期视频中介绍过一个开源项目 Cloud Code Router，它可以将任意大模型 API（包括一些免费模型）接入 Cloud Code。关于 CCR（Cloud Code Router）的具体使用方式，可以参考上期视频。使用 Cloud Code Router 的启动命令是 `ccr code`。

接下来我们看第一个最重要的命令：`/init`。使用这个命令可以让 Cloud Code 通读当前文件夹下的所有文件。Cloud Code 会分析当前项目，并将其学到的知识保存到一个名为 `cloud.md` 的文件中。后续与 Cloud Code 的所有对话，都会将这个文件作为上下文，这有助于 AI 更快地理解整个项目。当然，我们也可以手动修改这个文件，补充一些我们认为重要的信息，例如关于项目使用的 CSS 框架的知识。这个文件非常类似于 Cursor 中的 `CursorRule`，能让 AI 更加精准、快速地了解项目。

下一个命令是 `/compact`，用于压缩对话的上下文。执行该命令后，Cloud Code 会排除之前对话中无关紧要的内容，从而有效提高 AI 的专注力，并显著降低 Token 消耗。我们可以在命令后面输入具体指令，来告诉 AI 应该如何进行压缩。

第三个命令是 `/clear`，用于清除与 AI 的对话记录。每当要开启一个新任务时，都应该使用 `/clear` 来清理对话记录，保持一个干净的上下文，这有助于 AI 更专注地执行新任务。

在对话时，可以在指令前添加 `Sync`、`Sync Hard`、`Sync Harder` 以及 `Ultra Sync`。这并非某些「邪修版」的提示词技巧，而是 Cloud Code 官方文档中支持的方法，用于控制模型的思考长度。这四个指令的强度逐级递增。在开始处理一些比较复杂的问题之前，可以使用这些指令来提升 AI 的思考深度和代码质量。

在执行较困难的推理任务之前，可以添加一些提示词来增加 AI 的思考长度。

首先，我们可以输入一个叹号（!），将对话窗口切换至命令行模式。这样，用户无需额外开启窗口，即可执行临时的命令行命令。例如，我们可以执行 `npm install` 来安装 npm 依赖。使用叹号执行命令还有一个额外的好处：执行的过程与结果都会被加入 Cloud Code 的对话上下文中。AI 能够从对话历史里看到依赖的安装过程，从而避免后续重复执行相同的安装操作。

其次，输入一个井号（#）可以进入记忆模式。在此模式下，我们后续输入的内容都将被 Cloud Code 以文件的形式记录下来，成为 AI 的长期记忆。例如，我们可以输入「项目使用的 Next.js 版本是 15.4.1」。接下来，系统会提示选择记忆的存放位置，分为项目级别和用户级别。项目级别的记忆会直接保存在当前项目的 `cloud.md` 文件中；用户级别的记忆则保存在 Cloud Code 的配置文件中，对所有项目和文件夹生效。在 Windows 系统中，Cloud Code 的用户级别配置文件目录位于 `C:\Users\[用户名]\.cloudcode\cloud.md`，这里存放的就是对所有项目生效的全局记忆，也就是 Cloud Code 的系统提示词。

下一个重要命令是斜杠（/）加 `ide`。使用此命令前，需要在常用的 IDE 工具中安装一个插件。以 VSCode 为例，点击「扩展」（Extensions）进行安装。安装后，我们就可以在 VSCode 中选中一段代码，并询问 Cloud Code 其功能。Cloud Code 能够读取并解释所选代码的功能。此外，每当 Cloud Code 修改代码时，它会在 VSCode 中弹出一个对比页面，直观地展示修改前后的差异，方便用户决定是否接受这些修改。

Cloud Code 还提供了一种非交互模式。我们可以输入 `claude-p`（或 `ccr`，即 Claude Code Runner），后面跟上具体问题，来开启一次性的临时对话。Cloud Code 会在后台进行思考，并调用其工具来处理问题，处理完成后直接打印出结果。这种非交互模式让 Cloud Code 转变为一个命令行中的 AI 智能助手。

接下来，我们来看几个关于权限管理的技巧。首先是第一个命令：`/Permissions`。这个命令可以自定义一些规则。当我们把一个工具添加到 `allow` 列表里，Cloud Code 调用这个工具时就不再需要征求用户的同意，可以直接自动调用。我们来尝试添加一条规则，例如，我可以添加一条 `Bash` 规则，表示执行一个命令，括号里是命令的具体类型，这里我输入 `git commit`。这就意味着，以后执行 `git commit` 命令时，无需再申请权限，系统会自动执行。这里也可以选择配置的保存级别，可以保存到项目设置或用户设置中。

除了定义 `allow`，我们还可以定义 `deny`，也就是禁止 Cloud Code 使用某个工具。我们可以在 Cloud Code 的官方文档中查到所有内置工具的名称，总共有这么多。除了可以定义这些内置工具，还可以定义 MCP。我们可以输入 `MCP`，然后是两个下划线，接下来是 MCP 的名字。这样，我们就把一个 MCP server 添加到了 `allow` 列表里，以后 Cloud Code 调用这个 MCP 时就不再需要申请权限了。我们可以看到，下一次再使用 Neon 时，它就没有再申请权限，而是全自动地执行完成了。

还有一种更省事、更便捷的权限控制方法：在启动 Cloud Code 时，在后面加上两个横杠和 `Dangerously Skip Permissions`。如果使用的是 CCR，就是在 `CCR Code` 后面加上这一段。加上这个参数后，就赋予了 Cloud Code 最高的权限，它在使用任意工具、执行任意命令时，都不再需要申请权限，可以自行全自动执行。

`hook` 功能可以让 Cloud Code 在工作流程的特定节点执行某些操作。例如，我写代码时常使用 Prettier 工具来检查代码格式是否规范，执行的命令是 `npx prettier --check .`，用以检查当前目录下的代码格式。检查完毕，确认没有问题。

Sub-agent 很像编程中的子线程，它能让 Cloud Code 在后台开启多个子任务并行执行，从而加快任务的执行效率。每个 Sub-agent 都专注于一个小功能，这样就提高了结果的可预测性。正确使用 Sub-agent 来拆解复杂任务，可以有效提高任务的成功率。

我们回到 Cloud Code，输入斜杠（/）和「agents」，就可以创建自己的 Sub-agent。选择「Create」并按回车，这里可以选择将 Sub-agent 存放到项目级别还是用户级别，我选择项目级别。接着，我们选择第一个选项，让 Cloud Code 为我们生成一个。

在这里，我们使用自然语言来填写 Agent 的描述，主要说明它可以执行什么样的任务，以及希望达成什么样的结果。例如，我创建一个名为「代码审核大师」的 Sub-agent，让它帮我比较 Git 分支之间的差异，并提出审核意见。下一步是选择赋予这个 Sub-agent 什么样的工具权限，如果不知道怎么写，可以直接选择「Continue」。再下一步是选择一个模型，最后为它选择一个颜色，这里我选用红色。这样，我们的 Sub-agent 就创建完成了，其配置文件保存在项目目录下的指定地址中。按回车保存。

接下来，我们再创建一个 Sub-agent。描述为：「你是一个天气预报大师，使用联网工具可以查询天气。」按回车，这次的颜色我选择蓝色。这样，我们就拥有了两个 Sub-agent。

我们来测试一下，我让它帮我审查（review）这个分支，然后再查询一下青岛的天气。可以看到，AI 根据任务描述，将这一个任务拆解成了两个子任务，分别交给了红色和蓝色的两个 Sub-agent。这两个任务之间没有先后关系，它们是并行运行的。最后，Cloud Code 完成了代码审核，并给出了天气情况。我举的这个例子可能有点简单，主要是为了教学演示，大家可以发挥想象力，创造出更多有趣且实用的应用。

我们再来看一下 Sub-agent 的执行过程。Cloud Code 在拿到一个任务后，会根据 Sub-agent 的配置，自动拆分出子任务，并分配给不同的 Sub-agent 执行。每个 Sub-agent 都会获取到一份执行自己子任务所必需的、精简版的上下文，这样就保证了 Sub-agent 能专注地完成自己的任务。

Sub-agent 不会被主对话所污染，这提高了它的专注力。当所有的 Sub-agent 都执行完成后，最后由主 Agent 整合所有结果并给出完整的回答。

Claude Code 是一个纯命令行的工具，许多朋友可能不习惯使用。为此，GitHub 上有一个名为 Claudia 的开源项目，它是一个基于 Claude Code 打造的可视化桌面应用，拥有超过一万个 STAR。然而，该项目在 Releases 页面没有提供任何预编译的安装包，使用者只能自行从源码编译，过程非常繁琐。

幸运的是，社区中有其他开发者基于此项目制作了包含安装包的版本，我们可以直接使用。首先，在 GitHub 上找到 Claudia 项目，进入其「Insights」页面，在左侧点击「Forks」（即该项目的分叉）。在分叉列表中，我们找到 STAR 数量最多的一个。这个分叉项目对原版 Claudia 进行了修改，并提供了安装包。

进入该项目后，在 Releases 页面可以找到适用于不同操作系统的安装包。这里我以下载 Windows 系统版本为例，下载后一路点击「下一步」进行安装即可。

如果您的 Claude Code 是使用官网账户登录的，那么使用 Claudia 会非常简单，打开即可直接使用。另一种情况是，如果您的 Claude Code 是通过 API 或上期视频中介绍的 Claude Code Router 启动的，则需要额外进行一步设置。

具体操作是：在 Claudia 界面右上角找到「设置」，在「环境」选项卡中配置 API 的环境变量。这里以 Claude Code Router（CCR）为例：在 CCR 的控制台中输入 `/status` 命令，会显示一些认证信息。我们需要在 Claudia 中添加两个环境变量：
1. 第一个环境变量的 Key（键）是 `ANTHROPIC_AUTH_TOKEN`，其 Value（值）就是 `status` 命令中显示的 `Anthropic Token` 后面的字符串。
2. 第二个环境变量的 Key 是 `ANTHROPIC_BASE_URL`，其 Value 就是控制台中显示的相应 URL。

将这两项信息填写并保存设置后，通过 API 或 CCR 启动的 Claude Code 就可以在 Claudia 中正常使用了。

以上这些功能，我在之前的命令行教程中都已讲解过。如果您更喜欢可视化界面，那么在 Claudia 中进行操作也是一个非常不错的选择。此外，Claudia 还支持多标签页功能，方便同时管理多个对话。

Claudia 还有一个重要功能是时间导航线，它能更方便地管理历史记录和对话上下文。

举例来说，点击进入一个测试文件夹，里面有两个文件。我们可以点击「Create Checkpoint」来创建一个检查点。接下来，我让 AI 帮我删除一个文件，操作后系统显示「文件 2」被删除，文件夹里也确实没有这个文件了。

现在假设一个场景：我发现删除「文件 2」是一个误操作，想把文件还原回来，并且希望同时将对话记录也还原到删除之前的状态。这时，我们就可以找到原来的检查点，点击「restore」恢复它。这样一来，我们就通过检查点功能成功地将文件还原了。

此时，如果我问 AI：「你上一步干了什么？」它会回答：「上一步我只是回应了‘你好'。」这说明，我们使用检查点的功能，不仅回退了文件的改动，也回退了之前的对话历史，将所有状态都还原到了创建检查点的那一刻。

原版的 Cloud Code 只能回退对话内容，不能回退文件。而 Claudia 的检查点功能既可以回退对话内容，又可以回退文件，非常实用。
